# Session Stats API Specification

## Purpose

Defines the REST endpoint that exposes current token usage and limit for a user's active
Dev Studio session.

---

## Requirements

### Requirement: GET /api/v1/dev/session/stats

The server MUST expose `GET /api/v1/dev/session/stats`. The request MUST be authenticated
(same auth middleware as other `/api/v1/dev/` routes). The response MUST be JSON.

Response shape:
```json
{
  "session_id": "string",
  "tokens_used": 0,
  "cost_usd": 0.0,
  "token_limit": 0,
  "num_turns": 0
}
```

#### Scenario: Authenticated request returns current stats

- GIVEN a session with `tokens_used=750, cost_usd=0.015, token_limit=1000`
- WHEN `GET /api/v1/dev/session/stats` is called with a valid auth token
- THEN the response is `200 OK` with the current values

#### Scenario: No active session returns zero counters

- GIVEN the user has no recorded token events yet
- WHEN `GET /api/v1/dev/session/stats` is called
- THEN the response is `200 OK` with all numeric fields set to `0`

#### Scenario: Unauthenticated request is rejected

- GIVEN a request with no auth token
- WHEN `GET /api/v1/dev/session/stats` is called
- THEN the response is `401 Unauthorized`

---

### Requirement: session_reset Bridge Event

The `pkg/bridge/events.go` MUST define a `session_reset` event type constant. This event
MUST be synthetic (generated by the server, not the bridge subprocess) and MUST carry
`new_session_id` in its payload.

#### Scenario: Reset event payload is well-formed

- GIVEN the token limit is exceeded
- WHEN the server injects the reset event
- THEN the event type is `"session_reset"`
- AND the payload contains `"new_session_id"` with the newly generated UUID
